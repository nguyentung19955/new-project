TURRET MERGE — CORE FEEDBACK VFX & UX SPECIFICATION
Portrait mobile merge-defense | CO-OP / PvP / Solo
Art direction: bold, high-contrast, top-down cartoon machinery, matching the existing round turret heads and dark steel trays.
Authoring rules: ALL VISIBLE ART IS CHATGPT-GENERATED PNG. Flat #FF00FF backgrounds on requested generation sheets, then chroma-key to real alpha in the asset pipeline. Runtime may position, translate, scale, rotate, fade, tint, flip-book, reorder, clip existing rectangular sprite images if necessary, shake the camera, and briefly stop time. Runtime must NOT draw shapes, strokes, dashes, circles, borders, gradients, particles, text textures, glows, or lines. Use image assets for ALL such visible forms. Text/numerals already used by the game UI can remain the existing font/UI system; new star stamp symbols are PNG.

1. SCREENSHOT DIAGNOSIS AND CREATIVE TARGET

Observed in the supplied 832 x 1799 phone screenshot: on the lower player board, two circular turret heads overlap near the top-left cells. The source slot is marked by a thick, flat bright-green rounded rectangular outline, a faint duplicated turret/ghost remains behind, and the drag/target treatment competes with blue star badges and the existing colorful rarity rings. The top allied board and dense metal frame provide plenty of detail already. The merge interaction needs its own visual language rather than another UI frame laid over the board.

Replace the current treatment with 'MAGNETIC FORGE': a physical turret lifted from a steel socket, attracted into its equal-star partner, compressed into a forge spark, and re-created one star higher. The visual metaphor is industrial machinery + magical energy, not a touchscreen drag-and-drop form. The player must understand four facts immediately: what is held, which targets are legal, where it will land, and what star it becomes.

Visual hierarchy:
A. Held turret: brightest foreground element, roughly 1.12x base size, above the finger.
B. Valid hovered target: one vivid animated socket + compact star-up preview.
C. Other legal targets: quiet single rim breath, no full-screen pulses.
D. Invalid objects: unchanged or subtly desaturated; never paint the entire board red.
E. Board frames and enemy path: remain behind these effects.

Minimum principles: show only one strong animation focal point at a time; never cover an enemy's life-critical path readout; stop celebratory effects inside a 1-1.3 tile radius; no permanent bloom; no full-screen camera shake for ordinary merges; keep dragged sprite's star badge readable but attached to the held sprite. Always snap between tile centers, not art-boundary corners.

2. INPUT / MERGE RULES AND FEEL

Assume 5x3 grid, with occupied tile width represented by T = 1 tile and each turret's main circular silhouette ~0.65–0.78T. Suggested reference game-art sizes, independent of CSS pixels: turret head/base 128x128; 1 tile 160x160 authoring space; effects typically 192–256 per-cell for overspill. Scale based on current renderer's actual measured tile centers. If a screen renders a 50 px-wide tile, a 256 px art cell is scaled to about 80 px at 0.5T overspill on each side. Do not render all effects at native asset size.

Pointer-down: hit test against occupied owned player tile only. Drag begins after movement >= 7 screen px OR touch hold >= 90 ms. Keep direct taps available for inspect. On drag start store source ID, original coordinate, star, type, legal target IDs, captured pointer ID, and initial frame. Move held turret with finger but offset its center 0.55T UP from finger on portrait phones so the finger never hides it. Smooth position with a critically damped spring (~45–65 ms positional lag), bounded so it cannot visibly trail by more than 0.25T. The visual follows finger; logical hover uses raw finger hotspot projected onto tile, not the displaced sprite center. Permit slight easing only in visual position, never in legal hit test.

Default legal target: same turret type AND same current star, 1–6 stars, owned and not locked, unless a special turret explicitly overrides matching rules. At 7 stars, show cap/invalid feedback; don't suggest star 8. Re-evaluate when state changes. Hold hovered target only after pointer dwell >= 45 ms or when near its center within 0.36T; release it after 70 ms hysteresis or clear movement into another target. Ignore simultaneous touches or cancel gracefully. Preserve deterministic merge RNG and server/network authority.

Main merge visual is 780 ms: committing consumes input at pointer-up; gameplay merge state occurs once, logically at t=0 on the authoritative side (or with server confirmation); representation hides the old turrets at appropriate cinematic beats, then reveals final result at t~480 ms. This avoids desync. Suspend only the TWO involved turret attack visuals for up to ~300 ms where feasible; combat and enemy travel continue normally. Global hit-stop for gameplay is NOT recommended in live PvP; perform 35–45 ms local visual hit-stop on merge effects/turrets only. Camera shake is a tiny positional transform on board rendering (not the phone viewport or HUD).

3. PICK-UP: 0–150 ms

0–40 ms: finger hits the turret. It compresses to 0.95x with a quick 30 ms ease-out. The source socket gives a tiny mechanical 'click' (one rim PNG frame) while all other cells stay quiet.
40–105 ms: turret rises 0.55T above finger, scales 0.95->1.14 (easeOutBack), tilts -4 degrees then returns to 0 degrees. A pre-drawn elliptical metallic ambient-contact shadow stays on the source tile and fades from 0.50->0.20 opacity. Held unit gains a baked PNG cool edge glint; no procedural shadow ellipse.
105–150 ms: held turret settles at 1.10x. The original source tile shows a vacant 'ejected socket' plate PNG and a subtle darkened center, NOT a solid green box. An optional small 3-frame release spark at source plays once. Do not keep a translucent clone of the unit in its former position.
Easing: compress easeOutCubic; rise easeOutBack, small overshoot; tilt easeOutSine.
Code: duplicate display instance (same art) or move existing instance into a drag overlay layer; anchor center; apply position/scale/rotation/alpha only; hide the original game piece (not its base socket). Show sprite shadow and source socket PNG underneath. On cancellation restore one original unit only.

4. DRAG: WHILE FINGER MOVES

Held turret is 1.10x; slightly leans -3 to +3 degrees based on horizontal velocity, clamped. Add 2-frame engine/glint highlight only at meaningful velocity changes, or skip to reduce noise. No dashed line, no tracing particle tail, no ghost unit.
Every valid same-type/same-star target receives an understated 4-frame ring 'breath' over 800 ms at 0.5–0.75 alpha; the ring should be 4–6 px thick at 50 px tile scale, hugging the circular turret base rather than framing the square tile. One shared animation clock avoids random flicker. Do not tint the unit itself bright green; preserve colored role/rarity ring. Targets are visible during drag only, never at idle.
Nonmatching/blocked targets retain their normal colors with optional dark charcoal metal 'X latch' PNG when pointer hovers them. NEVER show every invalid target simultaneously. Empty cells are not merge targets (unless using a separate reposition rule).
If target changes while held, previous highlight fades out in 70 ms while next fades in 90 ms. Source stays a dark socket with embedded shadow. If dragging over ally board or path, no target cues.
Code: legalMatches[] drives PNG ring visibility; sprite instance positions follow tile centers; apply opacity only. The image is an authored segmented circular ring, not a shader/code stroke.

5. HOVER OVER LEGAL TARGET: 0–180 ms, LOOP WHILE HELD

0–65 ms: ring settles from 1.02 to 1.12x and becomes full intensity. The held turret is magnetized toward target center by 0.12T maximum, but finger still controls it; easing easeOutCubic. Do not fully snap until release or the gesture will feel stolen.
65–115 ms: a small baked 'two-prong magnetic clasp' PNG appears between the two round turret silhouettes; render as ONE compact, pre-drawn icon at midpoint, not a code-drawn connector. Optional if sprites are too crowded.
90–180 ms: preview chip flies upward 0.22T from target and holds: a large clean star glyph followed by +1 as PRE-BAKED ART (or a separately composited PNG number glyph if dynamic). The preview should indicate actual outcome, e.g. '1 -> 2' or simply '+1 STAR'; at 50 px board scale favor a large symbol + next-star-number badge, no microtype. Put preview above/right of target in nearest free region; clamp into board, and do not cover the user's finger. Preview doesn't promise type outcome if random-result rules apply: show 'STAR 2' only, not a specific turret art.
Upon exit, preview scales 1->0.85 and fades over 80 ms. Hold invalid target: one dark-red metal X/bump icon for 180 ms, not red whole-screen tint.
Code: calculate eligible resultStar = min(7, star+1) from gameplay rules; choose one of pre-rendered badge PNGs star_2.png..star_7.png; anchor at target center with positional offset. Pure transforms; no on-the-fly labels or circles.

T=0 on pointer-up. Freeze hover target choice for animation. Prevent both pieces from being interacted with again. If network/prediction applies, reserve slots and await authoritative commit before playing irreversible reveal; animation may show a brief tension/charge only while awaiting response.

An 8-frame radial machinery intake / spiral flips rapidly; its art already contains gear teeth and short inward streaks. A 55 ms low-frequency 'vacuum' sound plays over the inward motion.

At t=230, local visual hit-stop 40 ms: hold impact sprite frame and final target pose while enemies keep moving. Board renderer shifts +1.5 px, -1 px, then -1 px, +0.5 px over 70 ms (scale shake amount to 50 px tiles, not full-screen movement). 255–405 ms — ENERGY FORGE: a 6-frame spinning circular colored ring compresses and rebounds around target. Four large authored shard/spark sprites depart ~0.25T using rotations/translations; avoid dozens of particles. Keep brightness contained to target and immediate neighboring boundaries.
405–520 ms — NEW TURRET REVEAL: actual authoritative output turret appears at target center scale 0.60->1.20->1.00, alpha 0->1 in first 40 ms, easing easeOutBack. 490–650 ms — STAR STAMP: a large baked star-rank seal drops 0.20T down onto top-right edge of new turret. At impact it scales 1.35->0.90->1.0 (easeOutBack) and rotates -8->0 degrees. 650–780 ms — SETTLE: forge fragments/rim fade; new turret returns to normal animation; source cell returns to regular empty steel tile. Do not allow a second merge by holding the touch from before; require a fresh pointer-down. All temporary VFX are recycled by 780 ms.

Easing recap: snap easeInOutCubic; compression easeInCubic; reveal easeOutBack; pulse easeOutQuad; stamp easeOutBack. Apply scale with center anchors. This fixed authored timeline is the 'premium' merge feel; shorten only in accessibility reduced-motion mode (see below).

12. RUNTIME VFX STACK AND IMPLEMENTATION PSEUDOCODE

Order from back to front within the PLAYER board:
0 board floor / static tiles
1 under-unit socket/decal/target rings
2 regular turret bases + deployed turret heads
3 under-held contact shadow / held turret (drag overlay)
4 hover result preview + magnetic prongs
5 merge / summon central burst + shards
6 temporary star stamp and commander cast crest
7 HUD (untouched, always legible)
Enemy path should ordinarily render above distant board VFX only where the two overlap; no merge effects may cover opponent board or fixed bottom HUD. Use a clip rectangle for player board region if existing engine supports clipping, but do not generate a code-drawn mask; otherwise bound world-position and scale to stay within the allocated arena.

Pseudo-API (conceptual, adapt to current JS):
  vfx.play('merge_vacuum_intake', {x:target.x, y:target.y, frames:8, duration:110, scale:tilePx/160, anchor:[.5,.5]});
  tween(held, {x:target.x, y:target.y, scale:.32}, 110, 'easeInCubic');
  vfx.play('merge_impact_flash', {x:target.x, y:target.y, duration:85});
  vfx.play('merge_forge_ring', {x:target.x, y:target.y, duration:215});
  vfx.play('merge_star_stamp_pulse', {x:target.x+badgeOffsetX, y:target.y+badgeOffsetY, duration:190});
These methods draw ONLY source PNG pixels. Transformation functions update sprite properties; they must not create procedural visuals. For additional spark sprites, spawn up to 4 objects each showing an authored PNG shard and tween x/y/rotation/scale/alpha independently.

Interaction state machine:
IDLE -> PRESSING -> LIFTING -> DRAGGING -> (HOVER_VALID | HOVER_INVALID) -> RELEASED_VALID -> MERGE_PLAYBACK -> IDLE
  or DRAGGING -> CANCEL_RETURN -> IDLE.
On pointercancel, browser swipe interruption, orientation resize, game pause, enemy state change, or board update invalidating target: cancel held piece with no merge transaction. Make cleanup idempotent. Block overlapping merge animations on same tile, but keep unrelated gameplay visual transitions independent. Invalid drop never consumes a turn and never modifies merge state.

Authoritative state + presentation: do not defer actual rules for 780 ms merely to 'make effect feel slow'. Apply board transaction exactly once (local or server-authoritative), preserve selected output, and create a playback snapshot of old turret art. Display interim views from the snapshot while underlying game state is committed. If input/network timing causes a mismatch, end safely on correct final board. Sound cue at the same timeline timestamps. Queue incoming board diffs for those two visual cells only, then reconcile.

Mobile performance budget: cap 1 active major merge animation per affected tile, ~4 free shards per impact, no blur filters/canvas shadows, no layout reflow, pre-decode and cache atlas images, render at device-safe backing resolution (do not assume asset 256 means 256 output pixels), use alpha-tested cropped assets (transparent background). Avoid adding 10 simultaneous large alpha layers at 60 FPS. When many merges fire, merge some peripheral effects to a compact 420 ms fallback animation without sacrificing board state clarity.

Audio rough palette: pickup steel click, hover soft magnetic 'tick', merge suction + low metallic clap + high star ping, summon latch + pneumatic thunk, invalid dull clunk, level-up brass click, commander signature chord, wave siren chirp. All short and ducked; merge clang should not mask enemy attack SFX.
